Windows release build information: 4.1.0-local.11
=============================================

The Qt local-AI manager reuses the prepared optional/ installer payload via
Install-OptionalComponents.ps1 -Worker -NoConfigure. Consent is tied to the
catalog SHA256; full bundled licenses and model notices are checked before the
install button is enabled. The worker starts suspended, joins an owned Windows
Job, and only then resumes; cancellation closes that job and all its children.
The UI polls atomic progress JSON and retains resumable partial downloads.
Installing files does not change the application settings or defaults request.
Explicit Use actions apply a root/model immediately from the main window, or
stage a draft until the enclosing Settings dialog is accepted.
Delayed capture+translate uses Ctrl+Shift+Z; OCR-only capture uses Ctrl+Alt+I and
suppresses auto-translation for that result. A one-time migration removes old
OCR/inversion bindings of Ctrl+Shift+Z and repairs saved Ctrl+Alt+G duplicates.
CAT-Translate-3.3B is recommended and selected alongside Indra in optional setup;
fresh installations default to CAT, while updates preserve the existing model.
Hiding Crow's top-level windows defaults on, with a 150 ms desktop
redraw delay before grabbing. Cancellation and failures restore visibility and
window states. Shortcut validation includes duplicates/prefixes; registration
failure rolls back previous global bindings. tests/test_local_ai_management.cpp
uses an offline fixture installer to exercise consent, failure, retry and owned
child cancellation, separately from the real installed-payload checks.

RTX 3070 support: the optional setup installs the matching official b11318
CUDA 12.4 backend and NVIDIA runtime DLLs separately after license consent.
Their archives and extracted members are SHA256-pinned in optional-components.json.
The GPL Crow executable communicates over private JSON/loopback with the separate
MIT llama server; NVIDIA binaries retain their own EULA and third-party notices.
The NVIDIA driver and developer toolkit are not installed. CUDA is selected once
per physical GPU; Vulkan/CPU remains available when CUDA cannot initialize.
PLaMo CUDA uses a physical batch of 16 tokens to avoid nonfinite generation in
larger prefill batches. The server also clears recurrent data for independent,
uncached single-slot requests. Both source adjustments are in setup_local_models.py.
CAT-Translate-3.3B uses the official CyberAgent revision from catalog.json, its
original tokenizer/chat template, and a reproducible F16 -> Q4_K_M conversion.
The worker sends official fast-tokenizer IDs with the single-user chat wrapper
and decodes returned IDs with that tokenizer; the GGUF SentencePiece path does
not reproduce the official English BPE merges. The tokenizer is pinned separately.
Use tools/convert_cat_model.py to reproduce the separately released model.

Managed local models now accept per-model basic prompt templates and additional
instructions from the active settings store. Defaults come from catalog.json,
shared by the Qt UI and embedded Python worker. Known placeholders are replaced
once; source text and additional instructions remain literal. Additional
instructions are prefixed without adding a chat wrapper to PLaMo/Seed.
Codex receives editable basic and existing additional instructions as JSON
fields; response-schema and execution restrictions remain outside both fields.
The settings dialog stages drafts until OK; reset and model switches preserve
the same transaction. Empty basic instructions use the corresponding default.

GPU loading defaults to a 256 MiB reserve with automatic layer fitting. GPU
weights use load-mode none and no-host to avoid resident file mappings and
unnecessary host-pinned model buffers. On a single NVIDIA GPU, nvidia-smi's
global free VRAM limits Vulkan's potentially larger per-process budget. A
verified full-layer layout may promote the input embedding if measured spare
capacity permits; normal fitting remains its fallback. Allocation failures
retry with 512/1024 MiB reserve within one 120-second loading deadline.
The sentence-line-break setting defaults off and applies a shared formatter to
the editor and session/CLI. Source edits preserve undo, selection and IME input;
the formatter protects decimals, addresses, common abbreviations and paragraphs.
Codex discovery checks the native PATH, standard per-user standalone locations,
refreshed Windows PATH and native npm package binaries. No shell shim is run.
Explicit executable selections remain authoritative; authentication stays with
the user's separately installed Codex CLI.

Local translation validates English/Japanese by language code rather than
full QLocale equality. System-locale territory/number-format differences no
longer reject an automatic destination or a regional source. The requested
destination locale is preserved for the session's language display.
The installer supports selection of a default translation model and cleanup of
verified download/conversion inputs. It writes a one-time defaults request to
the per-user components.json descriptor. Qt applies it on the next application
start to the active native or portable settings store. Existing OCR settings are
preserved; a selected translation default explicitly changes the backend/model.
The optional setup's install button now stays disabled until the selection and
required license/eligibility consent are complete, including on retry.
Run tests/test_optional_setup_ui.ps1 with Windows PowerShell 5.1 to check its
WinForms state transitions without starting a worker or downloading models.
The release tag contains application sources, installer and setup scripts,
license manifests, and deployment documentation.

Build environment
-----------------
Windows 11 x64, MSVC 19.51.36260, CMake + Ninja, Qt 6.8.3 MSVC x64.
Release configuration, WITH_TTS=ON, WITH_PIPER_TTS=OFF,
WITH_PORTABLE_MODE=ON, WITH_KICONTHEMES=OFF, WITH_KWAYLAND=OFF.

The Qt binary packages are unmodified official Qt 6.8.3 packages. Their
source and binary SBOMs record upstream configuration and commit IDs.
The application was compiled with Tesseract 5.5.1 public headers and
Leptonica 1.87.0 headers, linking to the ABI-compatible Tesseract 5.5.3
and Leptonica 1.87.0 DLLs. Both Tesseract sources are supplied.

Other library versions, upstream URLs and archive checksums appear in
dependency-manifest.json. vcpkg source archives include the Windows build
recipes and patches. Microsoft Visual C++ runtime DLLs come from the
Visual Studio 2026 x64 redistributable directory (14.51.36231), including
Microsoft.VC145.OpenMP/vcomp140.dll for the native translation runtime.

Rebuilding
----------
1. Extract the application source ZIP, which includes pinned submodules.
2. Build Tesseract and Leptonica using the matching vcpkg port recipes in
   the attached dependency source archive, or an ABI-compatible release.
3. Run installer/Build-App.ps1, specifying the installed Qt prefix,
   vcpkg installed directory, Visual Studio vcvars64.bat and CMake/Ninja
   directories. Build all translation targets as well as the executable.
4. Prepare a directory containing only the Tesseract/Leptonica runtime
   DLLs and their transitive dependencies. For the published build these
   are libarchive, bzip2, giflib, libjpeg-turbo, libcurl, liblzma, libpng,
   libwebp/libsharpyuv, lz4, OpenJPEG, libtiff, zlib and zstd. Add permitted
   x64 Microsoft CRT DLLs from the Visual Studio Redist directory.
5. Obtain eng, jpn and osd from tessdata_fast tag 4.1.0 using
   installer/Get-Tessdata.ps1.
6. Prepare notices and dependency sources with Python 3.14:

   python installer/Prepare-ReleaseLicenses.py --qt-prefix <Qt-prefix> --tessdata-dir <tessdata> --output-dir <release-directory> --version 4.1.0-local.8

   Add notices for any additional runtime files to license-bundle/licenses.
   For the Microsoft CRT, include Microsoft's distribution terms/list:
   https://learn.microsoft.com/en-us/visualstudio/releases/2026/redistribution
7. Run installer/Build-Installer.ps1 with BuildDir, QtBinDir,
   DependencyBinDir, TessdataDir, InnoSetupDir, LicenseBundleDir,
   CMakeExecutable, OutputDir and Version. Inno Setup 6.7.3 was used.
   OptionalRuntimeDir must contain the runtime built by
   tools/setup_local_models.py --step runtime (the pinned PLaMo RoPE fix).
   Prepare-OptionalComponents.py includes its license/third-party notices and
   creates file hashes. PythonExecutable selects the build-time Python.

Qt DLLs and plugins are deployed dynamically. The Windows multimedia
backend is used. FFmpeg, Mesa software OpenGL, D3D compiler and DXC files
are not deployed. Windows supplies its graphics/system libraries.
No translation/Indra weights, Python environment, user settings or credentials
are bundled. An optional, per-user setup downloads only selected components
after explicit license consent. It uses official CPython, PyPI wheels and
pinned Hugging Face revisions. PLaMo weights are converted locally instead
of being redistributed. App-local native inference binaries are bundled with
their licenses. No system Python/PATH/registry changes are needed.

Redistribution
--------------
Upload the installer, corresponding application and dependency source
archives, and SHA256SUMS.txt together. Keep all license notices. The app
and its code changes use GPL-3.0-or-later; dependencies keep their own
licenses. This does not replace the licenses of separately fetched models.
